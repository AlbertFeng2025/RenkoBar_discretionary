How to use this page
  1. Copy this file (Renko_Recorder_Viewer.html) anywhere you like — e.g. into the Log Folder (default C:\temp) so it sits next to the logs.
  2. Double-click it to open it in Chrome or Edge, click Choose log folder and pick the indicator's Log Folder. Next time, just click Reconnect.
  3. Leave it open — it re-reads every 1.5 s. NinjaTrader keeps writing whether this page is open or not.
  4. Running recorders (green LIVE) are always on top. Recorders that are not running — removed, renamed, chart closed — are folded at the bottom.
  5. The rule — a NEW, UNIQUE Log Base Name every time you add or reload the indicator, and a different one on every chart. Never reuse a name from an earlier run. Recommended: instrument-date-time, e.g. MNQ10-28-2026-1PM (two charts at once: add the brick size, e.g. MNQ40-10-28-2026-1PM and MNQ80-10-28-2026-1PM). Remember the name and check that the LIVE header on this page shows exactly that name — it is also the first line of the chart's HUD (>> name <<) and the indicator's label on the chart (Recorder: name). Then you are sure you are watching the indicator that is running now.
    Safety net if a name is reused by mistake: a chart that reuses a name already running on a different chart (e.g. MNQ and NQ, or MNQ 40 and MNQ 80) does not take over the file — its HUD shows "!!!! NAME ALREADY USED"; reloading the same chart with the same name takes over (this page shows "restarted with the same name").
  6. Fresh start (optional): delete the old files ending in _state.json from the Log Folder. Running recorders write a new one on their next brick. Keep the .csv files — they are your history.

Each recorder writes <LogBaseName>_state.json after every brick. The line with a dark left edge is the deepest (money) layer. "0s in a row" = how many 0's follow the last 1 of that string. Market speed = average seconds per brick over the last N bricks of this session (set in the indicator, "Common 5. Speed"); "this brick open" counts up live from the last brick close. Check it matches the chart: the HUD line "state file … #N" on the chart and "update #N" here should show the same number. If the HUD shows "!! STATE FILE NOT WRITTEN" or "!! ANOTHER chart also writes", fix that first. The chart's HUD shows only the last layer (last 30 bits); this page shows every layer in full.
